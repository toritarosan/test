# 議題まとめ記事 編集規程・生成インストラクション

本書は、会議録アーカイブ（非公式）の「議題まとめ」記事を AI（または人間）が作成する際に
**必ず従う**規程である。目的は次の2点に尽きる。

1. **ハルシネーション（原典にない情報の混入）を構造的に防ぐこと**
2. **AIによる見解・解釈・評価の付与を排除し、記載事項に忠実な記事のみを公開すること**

---

## 0. 仕組みの全体像（多層防御）

AIの出力を信頼して公開するのではなく、**検証を通過しない記事は公開できない**構造とする。

```
[原典（要約済み会議録）]
      │  ① 生成：本規程（§1〜§5）に従いドラフト作成
      ▼
[articles.py（記事データ）]
      │  ② 機械検証：verify.py が原典と突合（§6）
      │     ERROR が 1 件でもあれば generate.py は出力を中止する
      ▼
[③ 人による確認（公開前の最終ゲート）]
      ▼
[公開（全記事に原典リンクを常設 → 読者が常に検証可能）]
```

> **限界の明示**：生成AIの性質上、「生成段階で誤りが起きない」ことは保証できない。
> 本規程が保証するのは「**原典と機械照合で矛盾する記事・規程に反する記事は公開されない**」
> ことであり、最終的な正しさは ②機械検証 + ③人の確認 + 常設の原典リンクで担保する。

## 1. 使用してよい情報源（これ以外は一切使用禁止）

- 原典（小金井市議会 非公式会議録）の会議録本文（要約セクションがある場合は要約を優先し、
  無い場合は全文文字起こしを情報源とする。文字起こしには話者誤りがあり得るため、
  発言者を断定できない発言は発言者名を書かない）
- 原典のファイル名・会期メタデータ（開催日・会議種別）
- **禁止**：AI自身の一般知識・推測・他サイトの情報・過去の報道。
  原典要約に書かれていない事実は、たとえ「常識的に正しそう」でも書かない。

## 2. 書いてよいこと・書いてはいけないこと

| 区分 | 内容 |
|---|---|
| 書いてよい | 議案・議題の内容、質疑・答弁・討論の要旨、採決・協議の結果、発言者名、原典に記載された数値・日付・固有名詞 |
| 書いてはいけない | AIの見解・感想・評価・予測・背景解説、原典にない因果関係（「〜が原因で」等）、原典にない数値・引用・人名、複数の数値からの**算術（合算・換算・比率計算）**、発言意図の推測 |

- 数値は**原典の表記のまま**書く（単位・桁を変えない。「約」の有無も原典に従う）。
- 議員側が示した試算・主張は「議員の提示」と帰属を付して書く（例：「議員の提示で累計約645.7億円」）。
- 原典要約に答弁内容が残っていない場合は、**創作せず**「（発言の詳細は原典参照）」と書く。

## 3. 中立性（行政と議会をフラットに扱う）

- 質疑・答弁は「**質疑（議会側）／答弁（行政側）**」の2カラム表で、同じ形式・同じ重みで併記する。
- 討論は「立場／討論の内容」の表で、賛成・反対を同じ分量感で併記する。
- **禁止語**（評価的・扇情的表現）：追及、糾弾、断罪、迫る、攻防、波紋、衝撃、露呈、杜撰、
  疑惑、紛糾、スクープ、「——」等（機械検証 V4 の禁止語リストが正）。
- 評価を含む語（批判・懸念・べき・疑問・主張・賛成・反対など）は、
  **発話者への帰属**（「◯◯議員は〜と述べた」「市は〜と答弁した」等）を伴う場合のみ使用できる。
  AIの地の文でこれらの語を使ってはならない（機械検証 V5）。
- 推奨する動詞：質問した／確認した／指摘した／要望した／提案した／説明した／答弁した／
  述べた／示した／協議した／可決された／付託された

## 4. 見出し・構成

- **タイトル**：議案番号・議題名ベースの記述式。キャッチコピー・比喩・疑問形・倒置は禁止。
  - 良い例：「議案第57号 令和8年度一般会計補正予算（第3回）：第一小学校の代替運動場整備」
  - 悪い例：「校舎改築で校庭が使えない——3,520万円の費用対効果を問う」
- **リード**：何が・いつ・どの会議で・どうなったか、の記録調1〜3文。
- **本文の標準構成**：
  1. 議案・議題の内容（表）
  2. 質疑と答弁（2カラム表）／討論（立場表）
  3. 結果（付託・可決・継続協議など）
  4. 関連情報（関連する会議・議員・他の議題まとめへのリンク）
- **リンク**：本文中の議員名は議員ページへリンクする。出典の会議ページ・原典URLを必ず付す。

## 5. 記事フッターの定型文

すべての記事に以下を明記する（テンプレートが自動付与）。

> 本記事は原典の要約データを再構成したものです。数値・固有名詞・引用は原典との
> 機械照合（verify.py）を通過しています。発言の正確な文脈は原典・録画でご確認ください。

## 6. 機械検証（verify.py）— 公開の必要条件

`generate.py` は出力前に全記事を検証し、**ERROR が1件でもあれば生成を中止する**。

| 項目 | 内容 | 判定 |
|---|---|---|
| V1 数値照合 | 記事中の全数値（複合数値は一体、単位込み、数字境界つき）が原典に存在するか | 不一致=ERROR |
| V1b 日付照合 | 記事中の日付（年月日・月日）が複合文字列として原典に存在するか（捏造日付の検出） | 不一致=ERROR |
| V2 引用照合 | 「」内の語句（4文字以上）が原典に逐語で存在するか | 不一致=ERROR |
| V3 固有名詞 | 議員名・議案/意見書/陳情/請願番号が原典に存在するか | 不一致=ERROR |
| V4 禁止語 | §3の禁止語を含まないか | 含む=ERROR |
| V5 帰属 | 評価語が帰属（発話動詞・話者・帰属列見出しつきの表）を伴うか | 伴わない=ERROR |

検証結果は `verify_report.txt` に出力される。実行方法：

```bash
python3 verify_one.py drafts/<draft>.py   # 1ドラフトを単体検証（作成者の自己チェック用）
python3 integrate.py                       # 全ドラフトを再検証し合格分のみ articles_auto.py に採用
python3 generate.py out                    # 検証込みで全生成（不合格なら中止）
```

大量の記事を作成する際は、作成者（AIエージェント）が `verify_one.py` で自己検証した上で、
中央の `integrate.py` が**自己申告を信用せず全ドラフトを原典と再突合**し、合格分だけを採用する
（防御の多重化）。

## 7. 新しい記事を作るときの手順（AI向けプロンプトの要旨）

新規記事の生成をAIに依頼する場合は、次の指示をそのまま与える：

> あなたは議会記録の編集者である。渡された原典要約**のみ**を情報源として、
> POLICY.md §1〜§5に完全に従い、articles.py 形式で記事データを作成せよ。
> 原典にない数値・引用・人名・因果関係・評価を一切書いてはならない。
> 原典要約に情報がない箇所は「（発言の詳細は原典参照）」と書け。
> タイトルは議案番号・議題名ベースの記述式とせよ。
> 質疑と答弁は「質疑（議会側）／答弁（行政側）」の表形式で同じ重みで併記せよ。
> 作成後、generate.py を実行し、verify.py の検証が合格（ERROR 0件）になるまで
> 修正せよ。検証を通らない記事を成果物としてはならない。

## 8. 人による確認（最終ゲート）

機械検証は「原典にない情報」「規程違反の表現」を検出するが、
**ニュアンスの歪み（正しい語を使った不公平な要約）までは検出できない**。
公開前に人間が以下を確認する：

- [ ] 質疑と答弁の分量・具体性が偏っていないか
- [ ] 一方の立場だけ詳細で、他方が省略されていないか
- [ ] 「結果」が原典の結論と一致しているか
- [ ] リンク先（会議・議員・原典）が正しいか
